# 商品价格库存证据 MVP

默认 `CATALOG_EVIDENCE_ENABLED=true`。本地可通过环境变量配置。
修改后需要重启 API。`false` 保留旧版用于 A/B，旧版仍可能放行虚构商品数值。
证据不足时只允许说明对应缺口，不会自动退回未校验的旧版。
默认 `NATURAL_RESPONSE_ENABLED=true`，模型依据校验后的证据组织面向顾客的语言。
已有合格的价格/历史答复可复用；知识及混合答复使用统一表达环节，不按商品或测试问题定制话术。
来源编号由服务端绑定。表达失败或违反数值、实体、来源检查时，保留证据摘要。

## 发布规则

- 保留现有 LangGraph 拓扑、工具注册及 `/api/chat` 的 `reply` 字符串。
- 在图节点收到 `catalog_search` 结果后，创建观察 UUID 和 UTC 返回时间，严格校验
  参数、商品 ID、非负整数 `price_cents`/`stock`、过滤条件及重复行冲突。
- 事实绑定商品 ID、观察 ID、查询参数、时间及来源字段路径，保存在该轮 trace 的
  `catalog_evidence` 中。时间是工具返回时点，不是数据库更新时间。
- 明确商品 ID 优先于模型选的 ID。没有明确 ID 时只展示候选，不声称完成名称或指代解析。
- 同商品的最近相关尝试覆盖较早事实，包括空结果、失败和非法字段；相同文本查询的
  空返回也不会复用旧候选。不同商品的失败不抹掉其他商品。
- 零价和零库存有效。空结果只表示本次条件没有可用记录，不能推断不存在、零库存或超预算。
- 截断只允许展示实际返回的记录。目录工具本身有 limit，回复不作全量断言。
- 价格用整数分格式化；商品 ID 只允许安全字符。不渲染模型 summary、数值草稿或不受约束的商品标题。
- 字段检查不调用 LLM、不新增数据库查询；自然表达可能新增一次模型调用，原生和 MCP 使用相同校验路径。

## MVP 显示边界

本阶段没有 AnswerPlan，也不依赖 Qwen JSON 输出能力。模型产生的 JSON、非法 JSON 或
业务草稿均不作为商品价格库存的事实来源。价格库存事实仍来自服务端校验；
最终语言可以由模型组织，受数值、商品绑定、历史范围和引用检查约束。
第一阶段曾对混合问题提示另行提问。第二阶段已由独立子问题组合器恢复完整知识片段及
现有订单工具记录，不拼接模型原始草稿；证据缺失仅影响对应部分。独立订单仍沿用原链路。
知识摘录不表示语义已验证，订单记录展示不表示新增状态一致性校验。历史数字回顾也需
经过已捕获的商品证据，旧记录缺少证据时不再直接放行模型数值。

`verification.presentation`记录是否复用模型答复、新增表达调用、回退原因及被拒草稿。
完整知识快照保留在`verification.parts`和trace，正文只概括与问题有关的内容。
`semantic_entailment=not_measured`：确定性检查不证明任意改写与原文语义等价，否定及条件仍需评测。

`verification.catalog` 区分执行成功、观察状态、已发布事实与缺失项；`draft_checks`
保留被丢弃草稿的旧引用诊断，顶层引用校验对应最终回复。
完整验证结果由现有会话提交逻辑保存，未引入新数据库。

当前不保证数据库记录在现实世界真实、不保证模型工具选择正确，也不验证订单或知识结论。
未调用目录工具时，对价格库存问题/草稿的识别仍依靠有限规则，未覆盖的自然语言表述
不能据此宣称已全面防幻觉。第二阶段说明及真实模型评测步骤见 [混合咨询与A/B](mixed-business-ab.md)。

## 离线验证

```bash
.venv/bin/python -B scripts/test_offline.py tests.test_catalog_evidence
.venv/bin/python -B scripts/test_offline.py
```

运行器将 SQLite 访问限制到临时目录，并阻止当前进程 TCP 连接（含本地模型服务）。
现有 MCP 集成仅启动固定 stdio 子进程，传入临时数据库路径；子进程不继承 Python
socket 补丁，但测试只调用本地目录工具。模型均使用 Mock，Chroma 测试使用固定向量。
测试不安装依赖，不启动 GPU 服务，不操作项目 `data/`。退出时删除临时数据。

下一阶段可扩展按字段区分的订单状态，再为知识引入完整摘录或经审核事实；不要直接把
目录的 `ok=True` 规则套到支付、退款或语义结论上。
