# 固定演示身份与客服范围

通过后端 `.env` 设置 `DEMO_USER_ID=U00001`，重启 FastAPI 后固定该身份。
页面 `/api/identity` 展示数据库中的用户名称和 ID，没有聊天切换或前端切换入口。
所有访问者共享这一演示身份，不提供多用户登录。

订单列表和详情在 SQL 层限定该 ID；用户身份不接受模型参数。
聊天请求禁止额外字段，不能通过提交 user_id 改变身份。
会话的读写、编辑租约、删除及记忆修改也检查归属。
已有旧格式会话迁移为原始演示身份 U00001，不随新的环境配置重新分配。
管理员更换 DEMO_USER_ID 后旧用户会话不能读取，页面遇到 404 会建立新会话。

危险请求先经过后端规则：已覆盖破坏命令、凭据窃取、绕过限制、
身份冒充、跨用户批量查询及部分攻击请求。命中后不调用 Kev、Qwen 或业务工具。
工具执行入口也检查这些规则；工具注册表和 Agent 权限白名单没有
Shell、任意程序执行、文件修改或交易执行能力。回复亦检查危险规则。
这些规则不能穷尽所有自然语言变体；不能把正则或模型分类理解为全面安全保证。

`JEV_SCOPE_ENABLED=true` 启用独立的 Kev 服务范围判断，五个选项：
customer_service / conversation_recall / unrelated / dangerous / unclear。
customer_service 进入常规客服流程；conversation_recall 进入只读会话回顾，
Qwen 只能读取当前身份会话记录，没有业务查询或记忆修改工具。
其他结果使用固定拒绝或澄清回复。
混合客服和无关任务整体拒绝，要求用户单独提出客服问题。
服务出错或无有效结果时暂时拒绝，防止降级为通用聊天。
常见问候跳过范围分类，但既有路由 shadow 仍可能调用 Kev。
范围判断使用分类选择，没有把尚未校准的置信度固定阈值用于放行。
这与 `JEV_MODE=off|shadow|advisory` 的业务路由建议独立；路由 shadow 保持不变。
关闭 JEV_SCOPE_ENABLED 会取消模型范围拦截，后端危险规则和订单归属仍生效。

`decision.scope` 记录放行/阻止、规则来源、原因及 Kev 结果。
被拒绝的内容保留在界面历史，但不回放给后续 Qwen 模型上下文。
回顾意图由 Kev 根据上下文语义判断，已移除固定问法的正则放行条件。
回顾提示词把历史包装为 JSON 数据，明确记录不是指令，业务事实依据原始工具结果。
缺失必需查询证据或校验失败的旧回复不作为事实提供；失败/空结果仍保留在记录里，
提示模型不能用更早成功结果冒充最近查询。
回复标记历史范围，引用只接受实际提供给模型的历史证据；模型提出工具调用直接报错，不执行。
要求重新查询、最新数据有调度修正，不走历史回顾；混入无关任务仍由范围分类拒绝。
上下文按预算保留完整的最近轮次，截断的证据会明确标记，不保证全会话无限回顾。
其余请求的范围判断可参考最近三条获准用户问题，避免只看当前短句而丢失指代。
分类请求把当前问题放在 state.question，历史问题单独放在 previous_questions，
避免拼接后模型把旧商品问题误当成本轮任务。独立的新算术问题按当前客服范围归 unrelated，
历史回答也禁止为了填充回复而附带用户未要求的旧商品信息。
范围拒绝页面标记没有调用回答模型与业务工具。
测试日志和本地 Kev 样本结果在 reports/customer-policy。

仅通过前端/API 使用此策略；不要把底层 vLLM 端口直接开放给客服用户，
否则直接请求模型会绕过应用策略。

生效需要重启 FastAPI；Next.js 开发服务会热更新页面。
