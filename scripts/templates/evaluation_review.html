批次概览

A = legacy：证据约束关闭；B = evidence：证据约束开启；C：证据开启 + Kev 领域建议；D：证据开启 + Kev 领域建议和入口范围分类。新工作流：Qwen_only 使用协调器；Kev_route 增加领域建议及校验后的直达路径；Kev_scope 再启用范围分类。

P50 / P95 为整轮请求耗时；Token 均值仅覆盖用量完整的轮次。各版本样本及审核分母分别展示，未知值用 — 表示。原 legacy / evidence 与 C / D 分批执行，硬件负载未独立测量。

逐轮审核维度

百分比同时显示已审核分母；误拒答率越低越好，其余维度越高越好。AI 初审与人工复核来源见上表和逐条记录；不适用项不进入该维度分母。

怎样判断指标、回复与执行流程？
检查维度审核依据如何看待好坏
任务完成逐项拆出问题要求，核对每个可完成子任务；数据缺失时是否准确解释对应缺口。同一保留集上越高越好；接口失败计入任务失败，不能只审查成功请求。
事实一致核对基准数据库、知识原文、商品实体、金额单位、时间范围与否定条件。不支持的功能不能说支持；只拒答可避免编造，却不代表完成任务。先报告审核覆盖率。
误拒答原资料有答案却拒绝可回答部分；纯无答案问题标“不适用”。越低越好，必须说明分母。混合问题只完成一部分也要核对剩余部分是否本可回答。
流程符合预期角色分工、必要工具、依赖顺序、参数和实体交接、失败处理、最终证据使用。结构检查不满足时优先排查；满足后仍需核对参数和语义，不能只按固定工具序列打分。
Kev 分类范围分类是否误拦截正常客服请求；领域建议是否适合当前任务，置信度是否达到实际采用门槛。分类接口成功不等于分类正确；规则拦截和模型分类分开计算。当前样例不是完整分类保留集。
延迟与资源同模型、同预算和可比任务完成质量下比较请求 P50/P95、调用数与完整 Token。通常越低越好；少回答或误拦截造成的“节省”不视为改进。调用墙钟时间不是 GPU 计算时间，未测量显存、能耗及金额。

流程清单是在运行后补充的审核辅助，不是独立盲测标签。旧批次未保存完整模型消息和节点时间戳；新工作流批次保存模型输入/输出、角色、调用时间及 Kev 请求/响应。按原件展示，不重建未记录数据，不要求或展示隐藏思考。
